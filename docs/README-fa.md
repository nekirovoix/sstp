# SSTP Deploy Manager

برنامهٔ گرافیکی Windows برای:

1. اتصال SSH به سرور Ubuntu و نصب/تنظیم SoftEther SSTP با گواهی Let’s Encrypt.
2. ساخت پروفایل SSTP داخلی ویندوز و اتصال با نام کاربری/رمز دلخواه.

## استفاده

- DNS دامنه باید قبل از دپلوی به IP عمومی سرور اشاره کند.
- پورت‌های TCP 22 (یا پورت SSH)، 80 (برای صدور گواهی) و 443 (SSTP) باید در دسترس باشند.
- برای دپلوی از کاربر `root` استفاده کنید. کاربر غیرروت باید `sudo` بدون رمز داشته باشد.
- رمزها در تنظیمات برنامه ذخیره نمی‌شوند و گزارش برنامه نیز آن‌ها را چاپ نمی‌کند.
- بار اول اثر انگشت کلید میزبان SSH نمایش داده می‌شود؛ فقط پس از تطبیق آن را تأیید کنید.
- فایل EXE امضای دیجیتال ندارد و ممکن است Windows SmartScreen هشدار دهد.

## خروجی ویندوز

پروفایل با مشخصات زیر ساخته می‌شود:
- Tunnel type: SSTP
- Authentication: MS-CHAP v2
- Full tunnel (Split tunneling disabled)
- Encryption level: Optional؛ کانال SSTP همچنان با TLS رمزگذاری می‌شود.

## رفتار رمز VPN

- هنگام اجرای برنامه یک رمز امن ۱۶ کاراکتری به‌صورت خودکار ساخته می‌شود.
- می‌توانید آن را با هر رمز غیرخالی دیگری جایگزین کنید؛ محدودیت حداقل ۶ کاراکتر حذف شده است.
- اگر هنگام دپلوی فیلد رمز خالی باشد، برنامه بدون خطا یک رمز امن جدید تولید می‌کند.

## نسخه 1.2

- نصب نیمه‌کارهٔ نسخه قبلی به‌صورت خودکار شناسایی و تعمیر می‌شود.
- فایل تنظیم ناقص SoftEther قبل از بازنشانی با پسوند `backup` نگهداری می‌شود.
- مقداردهی رمز مدیریتی SoftEther به روش تعاملی و قابل‌اعتماد انجام می‌شود.
- نوار پیشرفت دانلود SoftEther دیگر گزارش برنامه را شلوغ نمی‌کند.

## نسخه 1.3

- مقداردهی اولیه SoftEther از رابط مدیریتی محلی `localhost:5555` انجام می‌شود.
- برنامه تا ۴۵ ثانیه منتظر آماده‌شدن رابط مدیریتی می‌ماند.
- پس از نصب گواهی و فعال‌شدن SSTP، مدیریت به پورت 443 منتقل و پورت‌های اضافی بسته می‌شوند.
- خطای `Protocol error / Error code 2` هنگام راه‌اندازی اولیه برطرف شده است.

## نسخه 1.4

- اگر مدیریت SoftEther روی TCP 443 در دسترس نباشد، برنامه از `localhost:5555` استفاده می‌کند.
- دسترسی خارجی به پورت 5555 با iptables مسدود و این قانون با systemd پایدار می‌شود.
- SSTP همچنان فقط روی TCP 443 ارائه می‌شود.
- تمدید خودکار گواهی می‌تواند از 443 یا 5555 محلی استفاده کند.
- خطای کد 28 پس از صدور موفق گواهی رفع شده است.

## نسخه 1.5

- نتیجه دستور `ServerCertSet` بررسی و در `/var/log/sstp-cert-import.log` ذخیره می‌شود.
- اگر `fullchain.pem` پذیرفته نشود، برنامه `cert.pem` را امتحان می‌کند.
- برنامه گواهی واقعی ارائه‌شده روی TCP 443 را می‌خواند و تطابق آن با دامنه را کنترل می‌کند.
- تا زمانی که گواهی معتبر دامنه واقعاً ارائه نشود، دپلوی موفق اعلام نمی‌شود.
- خروجی اضافی PowerShell/CLIXML در مرحله ساخت پروفایل کاهش یافته است.

## نسخه 1.7

- خطای Certbot دیگر نادیده گرفته نمی‌شود و دپلوی بلافاصله متوقف می‌شود.
- گواهی اصلی `cert.pem` مستقیماً در SoftEther نصب و زنجیرهٔ میانی جداگانه از `chain.pem` بارگذاری می‌شود.
- SSTP پیش از نصب گواهی فعال می‌شود تا گواهی عمومی با نمونهٔ خودامضا جایگزین نشود.
- اعتبارسنجی با مقایسهٔ اثر انگشت SHA-256 و بررسی کامل زنجیرهٔ ارائه‌شده روی TCP 443 انجام می‌شود.
